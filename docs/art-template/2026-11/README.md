## How to use this package

- Wire the app to **page IDs and slots**, not to filenames. IDs (like `page_03`) never change.
- Each page folder has fixed filenames: `clean.<ext>`, `markup_N.<ext>`, `layers.psd`, `coords.json`, `other_N.<ext>`.
- `clean` is the real game artwork. `markup` images and `coords.json` show where things go.
- `manifest.json` lists every page, slot, note and coordinate item in flow order.
- Artwork must stay swappable: load images by slot path so new art can be dropped in without code changes.

## Coordinate convention

- Values are fractions of the image (0 to 1). Origin is the top-left corner.
- `point`: x, y = center.
- `box`: x, y = top-left corner, w, h = width and height.

### How a scrolling screen is built

1. A top bar and a bottom bar stay on screen (the controls page for that screen: `page_14` to `page_17`).
2. Between them the content scrolls as one page: `page_11` (top piece) once, then the recipe drawn by the app over a parchment
   centre with `page_12` repeated down the sides, then `page_13` (bottom piece) once after the last line.
3. Ingredients, directions, checkboxes, timers and grocery rows are always drawn by the app. They are never placed by coordinates.

All new placeholders are 841 px wide, the same width as the existing pages, so existing brushes and textures match.
The red boxes on the controls placeholders are where each control sits; `coords.json` holds the same boxes as fractions of the image.
